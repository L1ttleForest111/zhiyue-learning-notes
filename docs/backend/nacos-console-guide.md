# Nacos 控制台在看什么

本文面向还没接触过 Nacos 的前端同学。

可以先把 Nacos 理解成后端服务的“通讯录”和“配置中心”：

- **通讯录**：服务之间互相调用时不写死 IP，而是按服务名查找当前在线的实例和调用地址。
- **配置中心**：集中保存数据库、Redis 等配置，后端启动时按配置名读取。

> 打开控制台后，先在左上角选择命名空间。本地和 QA 使用的都是 `dev`。选错命名空间时，看到的是另一套环境的服务和配置。

## 一、服务列表

进入“服务管理”后，在 `dev` 命名空间中按服务名搜索。

常见服务名：

| 服务 | 服务名 |
| --- | --- |
| 运营端用户中心 | `vibe-user-center-admin` |
| 运营端商户中心 | `vibe-merchant-center-admin` |

服务名末尾通常表示服务面向的客户端：

- `admin`：运营端后台；
- `app`：小程序端。

服务列表中的主要列含义如下：

| 列 | 含义 |
| --- | --- |
| 集群数目 | 该服务名下分成了几组。不特别配置时都在默认组，数目为 1。 |
| 实例数 | 仍挂在服务列表中的进程个数。一台电脑上的一个端口算一个实例。 |
| 健康实例数 | 其中心跳正常、会被其他服务选中调用的实例个数。 |
| 触发保护阈值 | 健康实例是否已经少到保护线以下。`false` 表示未触发，调用方只访问健康实例。 |

点进服务详情，可以看到每个实例的 IP、端口、健康状态和元数据。本机服务启动并成功注册后，这里会出现当前电脑的地址。

## 二、集群

集群是同一服务名下的进一步分组。调用方查找服务时，使用的仍然是 `vibe-user-center-admin` 这样的服务名，Nacos 再根据集群决定优先调用哪一批实例。

这里的“自己”指**正在发请求的服务实例**，不是正在查看控制台的人。“自己那一组”指与调用方注册时使用相同集群名的实例。

例如，北京机房的商户中心使用集群名 `BJ`。当它向用户中心请求数据时，会优先从集群名同样为 `BJ` 的用户中心实例中选择一台；同组没有健康实例时，才会尝试其他集群。

因此：

- 集群数目表示分组个数；
- 集群变多后，请求会优先留在调用方所在的组；
- 集群数目多不代表服务更好；
- 本地未单独设置集群名时，所有实例都属于 `DEFAULT`，集群数目显示 1 是正常的。

要在列表中认出自己的实例，可以查看：

1. 详情中的 IP 和端口；
2. 元数据中的 `zone`，本地环境通常是当前系统用户名。

## 三、配置列表

控制台左侧“配置管理”保存数据库、Redis 等配置正文，这些内容不放在 Git 仓库中。查看前仍需确认命名空间为 `dev`。

每一行代表一份配置：

| 字段 | 含义 |
| --- | --- |
| `Data ID` | 配置文件名。 |
| `Group` | 配置所属分组，项目中使用 `DEFAULT_GROUP`。 |

配置名通常能对应到后台服务：

| Data ID | 用途 |
| --- | --- |
| `vibe-user-datasource.yaml` | 用户中心数据库配置。 |
| `vibe-merchant-datasource.yaml` | 商户中心数据库配置。 |
| `common-*.yaml` | 多个服务共同使用的配置。 |

每个后台项目的 `resources/bootstrap.yml` 不保存这些配置正文，只声明启动时需要从 Nacos 拉取哪些 `Data ID`。

例如，AI 中心的 `bootstrap.yml` 中如果声明了：

- `vibe-ai-datasource.yaml`；
- `vibe-ai-redis.yaml`；
- `common-feign.yaml`。

那么这些名字就应当能在 `dev` 命名空间的配置列表中找到。判断一条声明对应哪行配置，需要同时核对：

1. `data-id` 对应列表中的 `Data ID`；
2. `group` 对应列表中的 `Group`；
3. `namespace` 对应当前命名空间 `dev`。

`common-datasource.yaml` 与 `vibe-ai-datasource.yaml` 是两条不同配置，只是匹配方式相同。

> `spring.application.name`（例如 `vibe-ai-center-admin`）对应左侧“服务管理”中的服务名，不是配置列表中的 `Data ID`。

## 四、项目里的 `bootstrap.yml` 怎么读

`.yml` 和 `.yaml` 是同一种 YAML 格式。YAML 用于编写配置，依靠缩进表示层级：

- 同一列对齐的键属于同一级；
- 向右缩进表示属于上一层；
- 行首的 `-` 表示列表中的一项。

它表达的对象和数组关系与 JSON 类似，只是通常不写大括号和方括号。

以 AI 中心的 `bootstrap.yml` 为例，整份配置位于 `spring` 下面。这不是 YAML 格式的强制要求，而是 Spring Boot 约定的配置结构。最外层改成其他名字后，文件可能仍是合法 YAML，但 Spring Boot 无法识别，对应配置也不会生效。

按缩进可以重点看以下几块。

### 1. `application.name`

表示服务名，例如：

```yaml
spring:
  application:
    name: vibe-ai-center-admin
```

在 Nacos 服务列表中，应使用 `vibe-ai-center-admin` 查找该服务。框架还会根据这个名字自动拉取 `vibe-ai-center-admin.yaml`，这份配置不需要再写入 `shared-configs` 列表。

### 2. `cloud.nacos`

`cloud.nacos` 最上层的地址和账号配置用于连接 Nacos。

其中：

- `discovery`：服务启动后把自己注册到服务列表；
- `config`：服务启动时从配置列表读取配置。

`discovery` 中的 `namespace` 表示命名空间，`group` 通常是 `DEFAULT_GROUP`。

### 3. `config.shared-configs`

`shared-configs` 声明启动时还要读取哪些配置文件。每一项通常包括：

```yaml
- data-id: vibe-ai-datasource.yaml
  group: DEFAULT_GROUP
  refresh: true
```

它对应 `dev` 命名空间配置列表中的一行：

- `data-id` 对应 `Data ID`；
- `group` 对应 `Group`；
- `refresh: true` 表示控制台中的配置修改后，运行中的服务可以重新读取。

### 4. `${变量名:默认值}` 占位符

下面这种写法表示“优先读取变量，没有传入时使用默认值”：

```yaml
${NACOS_SERVER_ADDR:127.0.0.1:8848}
```

- 传入 `NACOS_SERVER_ADDR` 时，使用传入的地址；
- 未传入时，使用 `127.0.0.1:8848`；
- 默认值中的 `:8848` 是端口，不是第二个占位符。

其他例子：

| 写法 | 含义 |
| --- | --- |
| `${NACOS_USERNAME:}` | 传了用户名就使用；未传时为空字符串。 |
| `${NACOS_PASSWORD:}` | 传了密码就使用；未传时为空字符串。 |
| `${NACOS_NAMESPACE:}` | 传了命名空间就使用；未传时为空字符串。 |
| `${PROMETHEUS_DATA_ID:noop.yaml}` | 传了就使用指定文件名；未传时读取 `noop.yaml`。 |

## 五、健康和不健康

每个服务实例会定时告诉 Nacos“我还活着”，这个过程叫心跳。

- **健康**：心跳正常。其他服务按名称查询时，可以获得该实例的 IP 和端口。
- **不健康**：心跳已经中断。进程退出、电脑休眠或网络断开都可能导致实例不健康。实例可能暂时仍在列表中，但默认不会被选中，之后会被摘除。

因此：

- 实例数：仍保留在列表中的实例数量；
- 健康实例数：当前真正可以被调用的实例数量；
- 两个数字相同：说明列表中的实例目前都正常。

## 六、和页面报错的关系

页面提示“权限快照加载失败：用户中心服务不可用”时，多半不是账号权限本身有问题，而是后端服务调用链路不可用。

门店列表之类的请求可能由浏览器直连本机端口，所以仍能返回 `200`。权限快照则由商户中心按服务名 `vibe-user-center-admin` 去 Nacos 查找用户中心。如果服务列表中没有健康的用户中心实例，这次调用就会失败，并出现上述提示。

可以按下面的顺序排查：

1. 确认命名空间选择的是 `dev`；
2. 在服务列表搜索 `vibe-user-center-admin`；
3. 检查“健康实例数”是否大于 0；
4. 进入详情，核对目标实例的 IP、端口和健康状态；
5. 如果本机实例未出现，检查用户中心是否启动成功、是否连接到正确的 Nacos、是否完成服务注册；
6. 如果实例存在但不健康，检查进程、网络和心跳状态。

## 七、快速对照表

| 想确认的问题 | 去哪里看 |
| --- | --- |
| 某个后台是否已注册并在线 | “服务管理”中的服务列表和实例详情。 |
| 后端服务之间会调用哪个 IP 和端口 | 服务详情中的健康实例。 |
| 同一服务为什么有多组实例 | 服务详情中的集群名。 |
| 数据库、Redis 配置是否存在 | “配置管理”中的配置列表。 |
| `bootstrap.yml` 会拉哪些配置 | `config.shared-configs` 中的 `data-id` 和 `group`。 |
| `spring.application.name` 对应什么 | “服务管理”中的服务名。 |
| 页面能访问部分接口，为什么仍提示用户中心不可用 | 浏览器直连接口正常，但商户中心通过 Nacos 未找到健康的用户中心实例。 |
