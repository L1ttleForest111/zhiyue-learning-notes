# Nacos 控制台在看什么

给还没接触过 Nacos 的前端同学。Nacos 是后端服务的通讯录：服务之间互相调用时不写死 IP，而是按名字来这里找「现在谁在线、打哪个地址」。

打开控制台后，左上角先选命名空间。本地和 QA 用的都是 `dev`。选错命名空间，看到的是另一套环境。

## 服务列表

在 `dev` 里按名字搜。运营端用户中心是 `vibe-user-center-admin`，商户中心是 `vibe-merchant-center-admin`。名字末尾的 `admin` 是运营端后台，`app` 是小程序端。

| 列 | 干什么 |
|---|---|
| 集群数目 | 这个服务名下面分成了几组。不特别配置时都在默认组，数目是 1。 |
| 实例数 | 还挂在列表里的进程个数。一台电脑上的一个端口算一个。 |
| 健康实例数 | 其中心跳还在、会被其他服务选中去调用的个数。 |
| 触发保护阈值 | 健康实例是不是已经少到保护线以下。`false` 表示没触发，调用方只打健康的那些。 |

点进详情，能看到每一台机器的 IP 和端口。本机启动并注册成功后，这里会出现你这台电脑的地址。

## 集群

集群是同一个服务名下面的再分组。查找时仍然用 `vibe-user-center-admin` 这一个名字，Nacos 再按集群决定优先打哪一批。

「自己」是正在发请求的那一台服务，不是看控制台的人。「自己那一组」是和它注册时集群名相同的那些实例。比如北京机房的商户中心集群名是 `BJ`，它向用户中心要数据时，会先在集群名也是 `BJ` 的用户中心里挑一台。同一组里没有健康实例时，才会改去其他组。

集群数目是分组个数。组变多之后，请求会先留在自己那一组，数目多不代表更好。本地没有单独设集群名，大家的集群名都是 `DEFAULT`，数目显示 1 是正常的。要在列表里认出自己的机器，看详情里的 IP，以及元数据里的 `zone`（本地是当前系统用户名）。

## 配置列表

控制台左边的「配置管理」放的是数据库、Redis 这类配置正文，不在 Git 仓库里。先确认命名空间是 `dev`。

每一行是一份配置。`Data ID` 是文件名，`Group` 我们用的是 `DEFAULT_GROUP`。名字能对上后台服务：`vibe-user-datasource.yaml` 给用户中心，`vibe-merchant-datasource.yaml` 给商户中心。`common-` 开头的是多个服务一起用的。

项目里每个后台的 `resources/bootstrap.yml` 不写这些正文，只写启动时要去 Nacos 拉哪些 `Data ID`。例如 AI 中心这份文件里的 `vibe-ai-datasource.yaml`、`vibe-ai-redis.yaml`，就是配置列表里应有的行。`common-datasource.yaml` 和 AI 中心这份 yml 不是同一条，对应方式一样：yml 里的 `data-id`、`group`，对上列表里的 `Data ID`、`Group`，再加当前命名空间 `dev`。

`spring.application.name`（例如 `vibe-ai-center-admin`）对的是左边「服务管理」里的服务名，不是配置列表里的 `Data ID`。

## 项目里的 bootstrap.yml 怎么读

`.yml` 是 YAML 文件，读作「雅ml」。全称原来是 Yet Another Markup Language，后来写成 YAML Ain't Markup Language。`.yml` 和 `.yaml` 是同一种格式。它用来写配置，靠缩进表示层级，和 JSON 里的对象、数组是一回事，只是不用大括号。同一列对齐的是同级，往右缩进就是上一行里面的字段，行首的 `-` 是列表中的一项。

以 AI 中心的 `bootstrap.yml` 为例，整份文件挂在 `spring` 下面。这不是 YAML 的要求，YAML 不规定键必须叫什么。这个后台用的框架是 Spring Boot，它启动时打开这个文件，并且只认事先约定好的键名。最外层写成别的名字，文件仍然合法，但这份配置不会生效。

按缩进可以分成这几块：

- `application.name`：服务名，这里是 `vibe-ai-center-admin`。服务列表里用这个名字找它。框架还会按这个名字，再自动拉一份 `vibe-ai-center-admin.yaml`，这一份不用写进下面的列表。
- `cloud.nacos` 最上面三行：连哪台 Nacos、用什么账号。
- `discovery`：启动后把自己登记到服务列表。`namespace` 是命名空间，`group` 是 `DEFAULT_GROUP`。
- `config` → `shared-configs`：启动时要去配置列表里读哪些文件。每一条 `data-id` 加上 `group: DEFAULT_GROUP`，对上 `dev` 命名空间里的一行。AI 中心这里会读 `vibe-ai-datasource.yaml`、`vibe-ai-redis.yaml`，以及 `common-feign.yaml` 这类多个服务共用的文件。`refresh: true` 表示控制台上改了这份配置，正在跑的服务可以重新读。

`${NACOS_SERVER_ADDR:127.0.0.1:8848}` 这种是占位符。冒号前面是变量名，冒号后面是没人传这个变量时用的默认值。

- 本地启动传了 `NACOS_SERVER_ADDR`，就用传入的地址。没传时，默认连本机 `127.0.0.1:8848`。默认值里的 `:8848` 是端口，不是第二个占位符。
- `${NACOS_USERNAME:}` 冒号后面是空的。传了用户名就用用户名，没传就是空字符串。密码、命名空间也是这样。
- `${PROMETHEUS_DATA_ID:noop.yaml}` 同理：传了就用那个文件名，没传就去找 `noop.yaml`。

## 健康和不健康

每个实例会定时告诉 Nacos「我还活着」，这叫心跳。

- 健康：心跳还在。其他服务查这个名字时，会拿到这个 IP 和端口。
- 不健康：心跳断了。进程退出、电脑休眠、网络断开都会变成这样。它可能还留在列表里，但默认不会被选中。过一段时间会被摘掉。

实例数是还留着的，健康实例数是现在能被打到的。两个数字一样，说明这些实例都正常。

## 和页面报错的关系

页面提示「权限快照加载失败：用户中心服务不可用」，多半不是账号权限本身有问题。

门店列表这类请求是浏览器直连本机端口，所以可以返回 200。权限快照是商户中心按名字 `vibe-user-center-admin` 去 Nacos 里找用户中心。列表里没有健康实例时，就会报这句。
