# 全栈质量检查工作流

## 目标

在每次完成一个功能、修复一个缺陷或准备提交代码前，快速确认前端、后端与依赖的基础质量。检查通过不代表业务绝对正确，但能尽早发现类型错误、构建失败、测试失败和已知高危生产依赖漏洞。

## 一键检查

在仓库根目录运行：

```bash
bash scripts/quality-check.sh
```

脚本依次执行：

1. `notes-web/npm run build`：TypeScript 类型检查与 Vite 生产构建；
2. `notes-web/npm audit --omit=dev --audit-level=high`：检查生产依赖的高危漏洞；
3. `notes-api/mvn verify`：后端编译、测试和 Spring Boot 打包。

当前基线已验证通过。前端构建会提示主 JavaScript 包超过 500 kB，这是性能优化提示而不是构建失败。

## 每次开发的审查顺序

1. **接口契约**：同步检查 `docs/api.md`、后端 Controller/DTO/VO 和前端 `api.ts`、`types.ts`；字段、错误码、分页和时间格式必须一致。
2. **前端体验**：确认加载态、空态、错误提示、重复提交和网络异常处理；用户内容不可直接使用 `dangerouslySetInnerHTML` 渲染。
3. **后端边界**：确认请求校验、异常响应、事务、资源不存在与数据冲突的 HTTP 状态正确；所有数据库查询必须使用参数绑定。
4. **数据与安全**：确认索引匹配查询条件，不记录敏感正文或凭据；数据库密码只从环境变量读取。
5. **验证与回归**：运行一键检查；对改动的核心流程补充或更新自动化测试。

## 自动修复边界

可直接修复的事项包括构建错误、类型错误、缺失校验、明显的异常映射问题、确定的安全默认值和文档漂移。

以下事项必须先明确业务规则，不能自动猜测后修改：

- 登录方式、用户角色、资源所有权和数据隔离；
- 数据删除、迁移和不可逆操作；
- 正文长度、复习规则、分页默认值等产品策略；
- 对外部署、反向代理、Cookie 与跨域策略。

## 已知后续改进项

- 为前端和后端补充自动化测试，并让 `mvn verify` 实际覆盖核心服务和接口；
- 使用 OpenAPI 或契约测试减少 `docs/api.md`、前端类型和后端实现漂移；
- 将较大的前端包按路由或功能拆分；
- 数据量增长后优化笔记列表的 N+1 查询，以及正文全文搜索；
- 部署到局域网或公网前，增加认证、授权和资源归属校验；仅依赖 CORS 不足以保护接口。

## 数据库索引迁移

新初始化数据库已经在 `note_tags.tag_id` 上创建索引。已有数据库需要在确认索引不存在后执行：

```sql
ALTER TABLE note_tags ADD INDEX idx_note_tags_tag_id (tag_id);
```

生产环境执行结构变更前应先备份并在测试环境验证。
